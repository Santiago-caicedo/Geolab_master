¿Cómo decide el sistema qué cálculos aplicar?

El dispatch de macros de cálculo en Geolab Master — estado actual.

⚡ Respuesta corta El sistema NO se basa en los diámetros medidos (D1, D2, D3) para escoger los cálculos. Esos diámetros son datos de entrada del ensayo, no determinan el camino. El dispatch se decide mucho antes, cuando el remitente crea la remisión y selecciona la dimensión del espécimen en un dropdown predefinido.

El flujo real (estado actual)

1
Remitente

Selecciona la dimensión del espécimen

Al crear la remisión, escoge una opción de un dropdown predefinido sin ambigüedad:
3" Cilindro
4" Cilindro
6" Cilindro
50mm Cubo
15×15cm Viga
No hay parseo de texto libre ni inferencia por tamaño — el remitente escoge explícitamente.
▼
2
Sistema (Muestra.save)

Auto-clasifica la geometría

Muestra.save() detecta el dropdown y mapea a geometria:
# ensayos/geometry.py DIMENSION_A_GEOMETRIA = { '3_pulg': 'cilindro', '4_pulg': 'cilindro', '6_pulg': 'cilindro', '50_mm': 'cubo', '15x15_cm': 'prisma', }
El valor de geometria queda persistido en DB (campo editable=False).
▼
3
Técnico

Mide los especímenes en hoja de trabajo

Ingresa diámetros/anchos, longitudes, peso y carga. Aquí los diámetros son inputs, no decisiones. La geometría ya fue establecida en el paso 2.
▼
4
Sistema (Strategy Pattern)

Dispatch automático a la macro correcta

ResultadoMuestra._macro consulta la geometría y obtiene la macro:
# ensayos/macros.py def get_macro(geometria): return MACRO_REGISTRY.get(geometria, MACRO_REGISTRY['cilindro']) # En ResultadoMuestra: @property def _macro(self): return get_macro(self.muestra.geometria)
Cada macro implementa sus propias fórmulas (NTC 220, NTC 2871, etc.) y calcula area_mm2, esfuerzo_mpa, porcentaje_desarrollo.

El mapeo completo: dimensión → geometría → macro

Dimensión (dropdown) → Geometría (DB) → Macro / Norma
3_pulg · 3" (7.62 cm) → cilindro → MacroCilindro — compresión estándar
4_pulg · 4" (10.16 cm) → cilindro → MacroCilindro — compresión estándar
6_pulg · 6" (15.24 cm) → cilindro → MacroCilindro — compresión estándar
50_mm · 50mm → cubo → MacroCubo — compresión NTC 220
15x15_cm · 15×15cm → prisma → MacroPrisma — flexión NTC 2871

¿Qué campos ve el técnico en la hoja de trabajo?

Los campos físicos en DB son siempre los mismos (diametro_d1..d3, longitud_l1..l3), pero el template los renderiza con etiquetas distintas según la geometría:

Geometría Columna 1 (mediciones) Columna 2 (mediciones) Campos extra
cilindro D1, D2, D3 (DIÁMETRO mm) L1, L2, L3 (LONGITUD mm) —
cubo A1, A2, A3 (ANCHO mm) L1, L2, L3 (LARGO mm) —
prisma b1, b2, b3 (ANCHO b mm) d1, d2, d3 (ALTURA d mm) luz_entre_apoyos
distancia_falla_apoyo
formula_flexion (A/B)
tipo_especimen_viga (F/C)

Sistema nuevo vs fallback legacy

Sistema actual

Dropdown predefinido

Campo: dimension_especimen

  • Sin ambigüedad — el remitente escoge directamente
  • Mapeo 1:1 a geometría (lookup en diccionario)
  • Se ejecuta en todas las muestras nuevas
  • Introducido en migración 0007 + backfill 0008
Fallback legacy

Inferencia por texto libre

Campos: diametro_longitud + unidad_diametro

  • Solo se ejecuta si dimension_especimen está vacío
  • Parsea texto: "3" + "pulg" → cilindro
  • Reconoce formato "AxB" para cubos/prismas (con tolerancias)
  • En cualquier duda → cilindro (fallback seguro)
  • Casi no se usa hoy — el backfill llenó todos los datos antiguos

📌 Resumen en una línea

El "camino" lo decide el remitente al elegir la dimensión del espécimen en un dropdown. Eso se traduce a geometria en el save() del modelo, y el Strategy Pattern (get_macro()) usa ese valor para escoger qué fórmulas aplicar — los diámetros medidos por el técnico solo son inputs de esas fórmulas, no parte del dispatch.
